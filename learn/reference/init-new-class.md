# 初始化学习课程

本流程用于新课程的开课准备, 或补全尚未配置妥当的课程. 完成后生成开始学习的 prompt, 不在本流程中展开正式教学.



## 1. 与学生明确学习目标

先确认学生想学的主题, 再了解学习动机与期望深度. 每轮只问少量关键问题, 不一次性抛出整张问卷.

优先询问:

- 为什么现在想学这个主题? 是遇到了具体问题, 还是出于兴趣?
- 学完之后希望能做什么?
- 是否有时间限制, 或明确不想涉及的内容?

学生不一定能准确描述目标. 如果回答模糊, 根据其表达提供 2-4 个具体的候选目标, 让学生选择、组合或修改. 候选目标只是帮助表达的假设, 不代表已经得到学生认可.

例如学生说 "想学 Rust", 可以给出:

1. 看懂基础语法与简单程序, 能判断 Rust 是否适合自己.
2. 独立写一个能处理实际任务的小型 CLI.
3. 理解所有权与借用, 能定位和解决常见编译错误.
4. 为实际项目使用 Rust, 掌握开发、测试与交付流程.

不要默认学生要精通这个主题, 也不要为了让目标显得具体而强行安排一个项目. 简单了解、解决一个疑问与深入掌握都是有效目标, 但应说清希望获得什么结果.

将访谈结果整理为:

- `target`: 学习目的与期望深度, 使用简短文字.
- `learning_results`: 具体、可观察的学习成果，初始化时为null.
- `constraints`: 时间、预算等课程限制.
- `out_of_scope`: 明确暂不学习的相邻主题.

向学生简要复述, 确认理解一致. 未明确的可选内容使用 `null`, 不自行补造.

## 2. 建立或补全课程配置

已有课程沿用原目录, 不因配置不完整而重复创建.

新课程先读取 `StudySpace/learn/learn-index.yml`, 确定下一个课程编号, 创建 `learn/<编号-主题>/`, 并更新课程索引. 不预建空的课件目录.

获得学生对目标和保存配置的确认后, 创建或更新课程的 `config.yml`:

```yaml
learn:
  target: 已与学生确认的学习目标
  learning_results:学生学习时掌握的可观察的东西，初始化时为null
  constraints: null
  out_of_scope: null

resources:
  available: null
  missing: null

progress: null
```

所有字段固定保留. 没有内容时使用 `null`; 有内容时, 除 `target` 外使用字符串列表.

此时资料与学习步骤尚未确定, 可以暂时为 `null`, 后续补全.

## 3. 确认是否有学生提供的资料

询问学生是否希望以指定资料为学习依据, 例如教材、课程、文章、视频或本地文件.

学生提供资料时:

1. 确认资料的 URL 或实际文件位置.
2. 阅读并评估其可信度、适用版本、内容范围与课程目标的匹配程度.
3. 核对关键内容及明显疑点. 无法确认的部分明确标注, 不把 "未发现错误" 等同于 "保证正确".
4. 按教学资料处理规则整理到 `materials/`, 保留来源信息, 并更新 `materials/materials-index.yml`.
5. 对错误、过时或缺失的部分, 使用可信来源修正或补充.

资料不可访问时, 请学生提供可读取的版本或补充权限, 不声称已经阅读.

学生没有提供资料时:

1. 先读取 `materials/materials-index.yml`, 检查是否已有适用资料.
2. 现有资料不足时, 使用可用检索工具寻找高质量、可信的来源.
3. 阅读并核对后, 按教学资料处理规则保存到 `materials/`, 更新资料索引.

不要求开课前收集完整主题的所有资料. 优先保证学习路线与第一阶段有可靠依据, 后续需要的资料可以逐步补充.

## 4. 补全资料与初步学习路线

更新 `config.yml`:

- `resources.available`: 已核对并整理好的 `materials/` 路径.
- `resources.missing`: 当前仍需补充的资料描述, 没有时为 `null`.
- `progress`: 与目标深度匹配的初步学习步骤.

学习步骤描述学生将获得的能力或理解, 不只是列出教材章节. 路线保持简短, 不将所有知识点提前展开.

初步路线不是固定承诺. 必要前置知识是否已掌握, 留到正式教学中通过针对性问题确认, 再按实际情况调整.

例如:

```yaml
progress:
  - 确认必要前置知识, 建立主题的基本认识
  - 理解核心机制, 完成一个小练习
  - 将所学应用于目标任务, 检查学习成果
```

向学生简要展示目标、资料情况与初步路线. 如果第一课所需资料仍然缺失, 先说明并处理, 不把课程描述为已经可以开始.

## 5. 交接给新的学习会话

准备完成后, 汇报:

- 课程目录.
- 已确认的学习目标.
- 可用资料与仍存在的资料缺口.
- 建议从哪一步开始.

初始化过程中可能已经积累较多访谈与资料处理上下文. 建议学生清空上下文或开启新会话, 再发送开始学习的 prompt. 这是建议, 不强制要求, 也不依赖某个客户端特有的清空命令.

生成 prompt 前, 确认目标、资料路径与初步路线已经保存到配置中. 不依赖新会话记住本次访谈, 也不把整段访谈复制进 prompt.

根据实际课程目录替换以下模板, 不留下未填写的占位符:

> 请开始 `StudySpace/learn/<编号-主题>/` 的学习.
>
> 先读取 `StudySpace/AGENTS.md`、`StudySpace/learn/AGENTS.md` 和该课程的 `config.yml`, 使用 `pi-teacher-cli` 获取我的画像与已掌握术语.
>
> 开课准备已经完成, 不必重复初始化访谈. 根据配置中的目标与学习步骤, 用少量问题确认必要前置知识, 再从适合我当前水平的位置开始教学. 如发现配置缺失或目标存在歧义, 只确认必要部分.
